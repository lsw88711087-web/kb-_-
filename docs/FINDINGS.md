# 실측 결과 종합

`docs/ROADMAP.md`를 대체한다. 로드맵은 가설 기반이었고, 이 문서는 **실제 측정값 기반**이다.
모든 수치는 `qwen3:8b` / 12건 정답셋 / Ollama 로컬 실행에서 나왔다.

---

## 1. 뒤집힌 가설 — 가장 중요한 부분

프로젝트 출발 가설 중 **일곱 개가 측정으로 부정되거나 수정**됐다.

| # | 가설 | 측정 결과 |
|---|---|---|
| 1 | 적대적 디베이트가 **판정 정확도**를 높인다 | ❌ 단발+RAG가 일관되게 같거나 높다 |
| 2 | LLM의 **순응 편향**을 억제해야 한다 | ❌ 48건 판정에서 관대화 오류 **0건**. 억제할 편향이 없었다 |
| 3 | 근거 인용 규칙(`COMMON_RULES`)이 품질을 올린다 | ❌ naive와 라벨 지표 완전 동일(58.3%, F1 0.556) |
| 4 | 디베이트가 우려를 2배 발굴한다 | ⚠️ 3건 표본의 우연. 12건에서는 동일했고, **구조 수정 후에야** 우위 확보 |
| 5 | 사실팩(계산값 주입)이 정확도를 올린다 | ❌ 라벨 적중률은 오히려 하락(83.3% → 66.7%) |
| 6 | 신뢰도 스코어가 오답을 예측한다 | ❌ 저신뢰 오답률 40% vs 전체 42%. **재현성만 재고 정확성과 무관** |
| 7 | 측정 노이즈가 12%p다 | ⚠️ 대부분 내 코드 수정 탓. 시드만 바꾸면 **라벨은 0%p** |

**살아남은 가설은 하나다.** 디베이트는 **우려 발굴(recall)** 에서 앞선다 — 단 구조를 고친 뒤에야.

## 2. 최종 측정값

### 조건: 온도 0.5, 사실팩 ON, 구조화 우려, 회의론자 독립 점검, 시드 1회

| 지표 | 단발+RAG | 디베이트+RAG |
|---|---|---|
| 라벨 적중률 | 66.7% / 66.7% | 50.0% / 66.7% |
| macro F1 | 0.645 / 0.645 | 0.321 / 0.478 |
| **우려 recall** | 73.8% / 79.7% | **87.2% / 78.8%** |
| 우려 precision | 46.5% / 51.2% | 42.9% / 46.5% |
| 우려 F1 | 0.571 / 0.623 | 0.575 / 0.585 |
| 평균 검출 수 | 4.3 / 4.3 | 5.7 / 4.8 |
| LLM 호출 | 12 | **60 (5배)** |

*(A / B = 시드 7000 / 20000)*

**해석**: 디베이트는 우려를 더 많이·더 정확히 찾지만(recall +6%p), 헛짚는 것도 늘고(precision −4%p) 라벨은 나쁘다. F1은 사실상 동률.

### arm 4종 비교 (구조 수정 이전, 시드 3회)

| arm | 적중률 | macro F1 | 위반원칙 재현율 | 호출 |
|---|---|---|---|---|
| naive (규칙·RAG 없음) | 58.3% | 0.556 | 44.4% | 36 |
| single_norag (규칙만) | 58.3% | 0.556 | 52.8% | 36 |
| **single (규칙+RAG)** | **66.7%** | **0.645** | 63.9% | 36 |
| debate | 58.3% | 0.405 | 62.5% | 180 |

**RAG의 기여만 확실하다** (+8.4%p, 원칙재현 +11%p). 규칙은 라벨에 기여가 없고 원칙재현에만 조금 기여한다.

## 5. 남은 문제

| 문제 | 근거 | 영향 |
|---|---|---|
| **심각도 인플레** | 우려의 84~91%가 `중대` | 상위 k 선별 무의미, 라벨 상향 압력 |
| **라벨-우려 교환관계** | 우려 늘리면 라벨 나빠짐 (recall +18%p ↔ 적중률 −16%p) | 두 지표를 동시에 못 올림 |
| **정답셋 12건, pass 2건** | — | "항상 warn"이 위험탐지 83%를 받는 구조 |
| **CASE-010·011 라벨 의심** | 4개 arm이 모든 실행에서 `fail` | CASE-011은 CASE-004와 **내부 모순** (같은 단정적 판단인데 warn/fail) |
| **조정례가 가공 샘플** | — | 모든 적중률이 잠정치 |
| **디베이트 비용 5배** | 60 vs 12 호출 | recall +6%p로 정당화 가능한가 |

## 6. 다음 한 수 — 심각도 정의 + 라벨 집계

세 문제를 동시에 건드리는 유일한 수정이다.

**① 심각도 정의를 명시하고 분포를 제약**

```
치명: 계약을 권하면 안 되는 수준 (감당 불가, 규제 한도 초과, 원금 전액 손실 가능)
중대: 조건 조정·타깃 변경이 필요한 수준
주의: 설명·고지 보강으로 해소되는 수준
경미: 참고 사항. 상품군에 일반적으로 존재하는 조항
→ 중대 이상은 최대 2개
```

**② 라벨을 심각도에서 기계적으로 집계** (심판 재량 제거)

```
미해소 치명 ≥ 1 → fail
미해소 중대 ≥ 1 → warn
그 외           → pass
```

**기대 효과**
- 심각도가 갈리면 `prec@3`이 의미를 갖는다 (현재 60%)
- 라벨이 결정론적이 되어 시드 변동(16.7%p)이 사라진다
- **우려를 많이 찾아도 심각도가 낮으면 `pass` 유지** → recall과 라벨의 교환관계가 끊긴다

## 8. 심사 대응 — 지금 말할 수 있는 것

**주장하면 안 되는 것**

- "디베이트가 판정 정확도를 높인다" — 측정으로 부정됨
- "순응 편향을 억제한다" — 편향이 관측되지 않음
- "신뢰도 스코어가 오답을 걸러낸다" — 상관 없음

**측정 근거를 갖고 주장할 수 있는 것**

- **RAG 그라운딩이 판정 정확도를 8.4%p 높인다** (58.3% → 66.7%, 4 arm 비교)
- **디베이트는 검토해야 할 우려를 더 빠뜨리지 않는다** (recall 83.0% vs 76.8%), 단 비용 5배
- **계산 기반 사실팩이 수치 환각을 차단한다** (DSR 4.1%인데 "DSR 근접" 등 3건 정확 기각, 오기각 0건)
- **우리는 우리 시스템의 실패를 유형별로 세어봤다** — 결함 14건을 측정으로 발견해 수정

마지막 항목이 실질적으로 가장 강한 카드다. **가설을 세우고, 측정하고, 일곱 개를 스스로 부정한 기록**이 있다.
