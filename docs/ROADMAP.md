# 개선 로드맵 — 피드백 정리와 우선순위

이 문서는 대화에서 나온 피드백·제안을 의존관계 순으로 정리한 것이다.
순번은 "먼저 하지 않으면 뒤가 헛일이 되는 순서"이며, 중요도 순이 아니다.

---

## 판단의 근거가 된 실측치

우선순위를 이렇게 정한 이유는 아래 측정값이다. 추측이 아니라 실행 결과다.

| 측정 | 값 | 함의 |
|---|---|---|
| 실제 모델 애블레이션 (3건) 적합성 적중률 | single 100% / debate 100% | **3분류 라벨로는 두 방식이 구분되지 않는다**(천장 효과) |
| 같은 실행의 위반원칙 재현율 | single 33.3% / debate **66.7%** | **우려 발굴 능력에서만 2배로 갈렸다** ← 유일한 변별 지표 |
| 정답셋 라벨 분포 | pass 2 / warn 5 / fail 5 | "항상 warn" 전략이 위험탐지 **83%** 를 받는다 (지표가 비관을 보상) |
| gold=pass 케이스로 실제 모델 검증 | **0회** | warn 편향은 아직 관측된 바 없다 (가설 단계) |
| 디베이트 1건 소요 | 47초 (사고모드 끈 후, 99초→47초) | 검증 실험 12회 ≈ 10분. 실험 비용은 장벽이 아니다 |
| 직업 키워드 매칭률 | 84% (58%에서 개선) | 나머지 16%는 기본 배수로 처리 |
| 테스트 | 25개 통과 | 회귀 안전망 확보 |

**결론**: 이 시스템의 실제 강점은 판정이 아니라 **우려 발굴**이다. 산출물과 지표를 거기에 맞추는 것이 가장 큰 개선이다.

## Phase 0 — 지금 막혀 있는 것 (선행 필수)

| # | 항목 | 왜 먼저인가 |
|---|---|---|
| 0-1 | **로컬 미커밋 4건 커밋 + 푸시** | GitHub 웹에서 같은 파일을 편집하면 충돌한다. 커밋 안 된 상태로 원격을 건드리면 방금 고친 것이 날아갈 수 있다 |

> 로컬의 `debt_cap_*`·확장된 `occupation_multiplier`와 충돌한다.

## Phase 1 — 측정 기반 (이게 없으면 어떤 개선도 증명 불가)

| # | 항목 | 근거 |
|---|---|---|
| 1-1 | **정답셋 확대**: gold=pass 2건 → 6~8건 (전체 12 → 30건 목표) | pass 케이스가 2건이면 warn 편향을 검출할 수 없고, "항상 warn"이 83%를 받는 채점 구조가 유지된다 |
| 1-2 | **지표 전환**: 주요 지표를 `hit@3 / recall@5 / MRR`로, 3분류 적중률은 부차로 | 라벨은 케이스당 1비트, 우려 목록은 여러 항목 → 12건이 24개 이상의 채점 단위가 된다 |
| 1-3 | **실패 유형 라벨링** 20~30건 (수치오류 / 조항조작 / 근거없음 / 스키마이탈) | "환각이 얼마나 줄었나"를 숫자로 말할 유일한 방법. 심사 자료로도 강력 |
| 1-4 | **`rules_only` arm 추가** | 하드게이트 도입 시 규칙만으로 맞는 케이스가 생긴다. 분리하지 않으면 "그냥 룰베이스 아닌가"에 답할 수 없다 |
| 1-5 | (선택) gold=pass 2건으로 warn 편향 실측 — 10분 | 편향이 실재하는지 확인. 없으면 관련 작업 전부 취소 가능 |

**측정 항목 정의**

```
hit@3      상위 3개 우려에 실제 분쟁 원인이 포함됐는가
recall@5   정답 위반원칙 중 상위 5개 안에 몇 개를 잡았나
MRR        실제 원인이 몇 번째로 제시됐나
warn_rate  전체 판정 중 warn 비율 (편향 지표)
채택률     사람이 "확인할 가치 있다"고 표시한 우려 비율 (유용성)
```

## Phase 2 — 산출물 전환 (가장 큰 개선)

판정기(verdict machine) → **검토 지점 안내기(triage)** 로 전환.

| # | 항목 | 비고 |
|---|---|---|
| 2-1 | 주요 산출물을 **우선순위 붙은 우려 목록 + 검증할 데이터원**으로 | `report.py`가 이미 `top_risks`/`top_recommendations`를 뽑으므로 절반은 있다 |
| 2-2 | **우려 유형 → 검증 데이터원 매핑 테이블** 신설 (10~15개) | 실무 가치의 핵심. "이 우려는 사내 급여이체 유지율로, 저건 KOSIS 몇 번 표로 확인" |
| 2-3 | **인용 ID 실재 검증** (작업 칩에 등록됨) | 우선순위 **상승**: 산출물이 "여기를 보라"가 되면 없는 조항을 근거로 한 우려는 분석가 시간을 직접 낭비시킨다 |
| 2-4 | 심판에 **우려 채택/기각 권한** + 기각 사유 명시 | warn으로 도망가는 대신 우려 개수로 도망가는 것을 막는다 |
| 2-5 | 3분류 라벨은 **부차 산출물로 유지** | 조정례 정답셋과 연결되는 유일한 고리. 브리프가 요구하는 "정확성 실증" 경로 |

**산출물 형태 예시**

| 우려 | 근거·앵커 수치 | 확인할 실제 데이터 | 신뢰도 |
|---|---|---|---|
| 우대조건 달성 불가 | 4개 동시 충족 추정 2.6% | 사내 급여이체 24개월 유지율, 카드 실적 지속률 | 높음 |
| 광고 오인 | 표시 6.0% vs 기본 3.7%, 단리 체감 절반 | 조정례 CASE-002 유형, 민원 이력 | 높음 |
| 저소득 세그먼트 부담 | payment_burden 0.9 | KOSIS 1~2분위 적금 보유율 31% | 중간 |

**포지셔닝 문구**: "판정하지 않습니다"가 아니라
**"판정 근거를 좁혀 컴플라이언스 검토를 가속합니다"**. 전자는 책임 회피로 읽힌다.

## Phase 3 — 계산적 보정 (사실팩·하드게이트)

LLM 판단을 그대로 다음 에이전트로 넘기지 않고 중간에 코드로 재계산한다.

| # | 항목 | 상태 판단 |
|---|---|---|
| 3-1 | **공통 사실팩** — `payment_burden`, `dsr`, `stressed_dsr` 등 파생 지표를 코드로 계산해 주입 | **채택**. 수치 오용(A형 환각)을 구조적으로 차단 |
| 3-2 | 사실팩 정의 공백 해소 — ① `product_payment_m` 시나리오 3개(최소/최대/여유자금 50%) ② 음수 여유자금은 값이 아니라 **플래그**로 | `max(surplus,1)`은 -10만원을 1로 만들어 "부담률 5000%"라는 새 환각원을 만든다 |
| 3-3 | **전달 형식** — `claim / evidence / computed / uncertainty / for_next_agent` | **채택**. 저비용 고효과. 단 옹호자·회의론자는 자연어 본문 + 구조화 헤더 절충 (8B에서 JSON 강제는 논증 품질을 떨어뜨린다) |
| 3-4 | **하드게이트 — 계산 가능한 것만** (감당능력, DSR, 스트레스 DSR) | **채택**. 1-4(`rules_only` arm)와 **반드시 동시에** |
| 3-5 | 하드게이트 확장을 위한 **스키마 확장** — Persona: `financial_literacy`, `investment_experience`, `risk_tolerance_grade`, `loss_tolerance` / Product: `risk_grade`, `complexity`, `requires_cooling_off`, `principal_guaranteed` | 실제 작업량의 대부분. Nemotron에 없어 **또 합성**해야 하고, 그러면 "합성값에 우리 규칙 적용"이라는 순환을 리포트에 명시해야 한다 |
| 3-6 | `manual_review` 라벨을 정답셋 3분류에 매핑하는 규칙 결정 | 정하지 않으면 채점이 성립하지 않는다 |

## Phase 4 — 모델링 (검증 경로가 있는 것부터)

| # | 항목 | 판단 |
|---|---|---|
| 4-1 | **가입의향 `P_interest` + 프로스펙트 가치함수** | **유망**. `est_attainment_rate`를 확률 시나리오로, 광고 금리를 기준점으로 두면 계산이 성립한다. 손실회피 2.25가 "최고금리 광고의 실망"을 정량화 |
| 4-2 | β 계수를 **KOSIS 보유율로 캘리브레이션** | 이게 4-1을 정당화하는 유일한 경로. `compare_holding_rates`가 이미 Spearman·MAE를 계산한다 |
| 4-3 | **우려 severity 서열 4단계**(경미/주의/중대/치명) + **계산 앵커링** | 회의론자가 자기 공격을 채점하면 인플레. 계산 가능한 항목은 사실팩에서 파생하고, 불가능한 항목(설명 보강 등)은 **severity 상한**을 둔다 |

## Phase 5 — 보류 (조건이 갖춰질 때까지)

| # | 항목 | 보류 이유 | 해제 조건 |
|---|---|---|---|
| 5-1 | **`Q_reg` 시그모이드 적합성 점수** | θ 계수 9개를 12건으로 검증 불가(과적합). 입력(`GoalFit`, `Understanding`)이 LLM 주관값이라 **환각이 입력단으로 이동**. 임계값 0.40/0.65 근거 없음 | 정답셋 50건 이상. 그전에는 **결정표**로 시작 |
| 5-2 | **warn 편향 수정** (개수 하한 제거, warn 정의 강화) | 산출물을 우려 목록으로 전환하면 대부분 해소되는 문제 | Phase 2 후에도 `warn_rate`가 높게 남으면 착수 |
| 5-3 | **옹호자 반론 턴 추가** | 순서 편향 완화 효과는 있으나 LLM 호출 +1 (시간 +20%) | 1-5에서 편향이 확인되고, 5-2로 해결되지 않을 때 |

## 다음 한 가지만 한다면

**Phase 0-2 (실데이터 반영)** 이다. 이유는 두 가지다.

1. 사실팩·하드게이트·세그먼트 분포가 모두 이 수치 위에서 계산된다. 나중에 바꾸면 그 위에 쌓은 검증을 전부 다시 해야 한다.
2. 이미 xlsx에서 추출해 두셨으므로 실제 소요가 가장 짧다.

그다음은 **Phase 1-1(pass 케이스 확대)** 이다. 이게 없으면 Phase 2 이후의 어떤 개선도 숫자로 증명할 수 없다.
