## 2. 현재 아키텍처

```
상품 정의 + 페르소나
   ↓
사실팩(facts.py) — 파생 지표 계산: DSR, 부담률, 스트레스DSR, 우대조건 동시충족률 등
   ↓
RAG 검색(rag/) — 금소법 6대 원칙 + 조정례. 평가 시 자기 사례 제외(정답 누출 차단)
   ↓
판정 — 세 방식
   · single    : 단발 1회 판정 (12회 호출)
   · debate    : 옹호자→페르소나→회의론자→페르소나→심판 5턴 (60회 호출)
   · ensemble  : 위 둘 병행. 우려는 합집합, 라벨은 single에서 (72회 호출)
   ↓
후처리 — ① 계산값과 모순되는 우려 기각  ② 계산값이 요구하는 최소 심각도로 승격
   ↓
산출 — 구조화된 우려 목록 {유형, 심각도, 앵커, 확인방법, sources}
```

**우려는 자유 텍스트가 아니라 구조화 객체다.** 유형은 `data/benchmark/concern_taxonomy.json`의 15종.

## 3. 측정된 사실 — 이걸 전제로 작업할 것

조건: `qwen3:8b`, 12건 정답셋, 시드 1회, 온도(토론자 0.5 / 심판 0.2)

> **아래 표는 심각도 수정 3종 이전 값이다. 라벨·우려 지표는 5절이 갱신본이다.**
> 계층별 정확도와 arm 4종 비교는 아직 재측정되지 않아 그대로 유효한 최신값이다.

| 지표 | single | debate | ensemble |
|---|---|---|---|
| 라벨 적중률 | 66.7% | 50.0~75.0% (불안정) | 66.7% |
| 우려 recall | 73.8~79.7% | 78.8~87.2% | 86.3% |
| 우려 precision | 46.5~51.2% | 42.9~46.5% | 41.7% |
| 위반원칙 재현율 (구 지표, 결함 15번 포함) | 66.7% | 70.8% | 83.3% |
| prec@3 | 63.3% | 60.0% | 53.3% |
| LLM 호출 | 12 | 60 | 72 |

**계층별 정확도 (ensemble 기준, 이 두 신호가 핵심) — `sev_A.json`으로 갱신됨**

```
교차확인(두 방식 모두 제기)  19/36 = 52.8%      단독  9/24 = 37.5%
심각도 치명   7/10 = 70.0%    중대  21/50 = 42.0%    주의  0건 발생
```

이전 값(치명 3/3=100%, 단독 20~30%)은 **더 작은 표본에서 나와 과장돼 있었다.**
교차확인 우위는 "2배"가 아니라 1.4배다. 주장할 때 이 값을 쓸 것.

**계층 서열은 세 arm 모두에서 단조롭게 성립한다 (역전 없음)** — 설계는 검증됐다.
```
single    T2 66.7%(6/9)  > T3 54.8%(17/31) > T4 14.3%(1/7)
debate    T2 77.8%(7/9)  > T3 40.5%(17/42) > T4  0.0%(0/2)
ensemble  T1 62.5%(5/8)  > T2 53.3%(16/30) > T3 31.8%(7/22)
```
T1은 교차확인이 필요해 ensemble에서만 발생한다.
재산출: `uv run python scripts/analyze_ablation.py outputs/sev_A.json` 의 8절.
**이 출력과 `concerns.py`의 `TIER_BASIS`가 어긋나면 `TIER_BASIS`를 고칠 것.**

**arm 4종 비교 (시드 3회)**: naive 58.3% / single_norag 58.3% / **single 66.7%** / debate 58.3%
→ **RAG만이 검증된 기여자**(+8.4%p). 근거 인용 규칙(COMMON_RULES)은 라벨 기여 0.

## 4. 측정으로 부정된 주장 — 다시 쓰지 말 것

| 주장 | 왜 안 되는가 |
|---|---|
| "디베이트가 판정 정확도를 높인다" | single이 같거나 높다 |
| "LLM 순응 편향을 억제한다" | 48건 판정에서 관대화 오류 **0건**. 억제할 편향이 없다 |
| "신뢰도 스코어가 오답을 걸러낸다" | 저신뢰 오답률 40% vs 전체 42%. **재현성만 재고 정확성과 무관** |
| "근거 인용 규칙이 품질을 올린다" | naive와 라벨 지표 완전 동일 |

**쓸 수 있는 주장**
- RAG 그라운딩이 판정 정확도를 8.4%p 높인다
- 병행이 위반원칙 재현율에서 15.0%p 앞선다 (90.0% vs 단독 75.0%) ← 수정된 지표 기준
- 교차확인된 우려는 단독보다 정확도가 1.4배 (52.8% vs 37.5%) ← "2배"는 구 표본의 과장
- 사실팩이 수치 환각을 정확히 차단한다 (오기각 0건)
- **결함 15건을 측정으로 찾아 고쳤다** ← 가장 강한 카드

## 5. 심각도 수정 3종 — **측정 완료**

세 가지를 고쳤고 `outputs/sev_A.json`으로 재측정했다 (12건, 시드 1회, seed_base=7000).

1. **심각도 정의 명시** — 프롬프트에 치명/중대/주의/경미 기준 + "중대 이상 최대 2개"
2. **계산값 → 심각도 승격** (`facts.SEVERITY_FLOORS`) — 하드 게이트를 라벨이 아니라
   심각도에 건다. 라벨 강제는 정답셋과 축이 달라 충돌한다(실측: 12건 중 2건 충돌)
3. **부담률 계산 수정** — 적금은 최소 납입액, 예금은 min(한도, 금융자산) 기준.
   예금은 자산을 옮기는 것이라 감당능력 '치명' 미적용

**승격 규칙의 정답셋 정합성 (사전 시뮬레이션)**
```
gold=fail 5건 → 전부 '치명' 발생     gold=pass 2건 → 승격 없음
```

### 재측정 결과 (`outputs/sev_A.json`)

| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| 라벨 적중률 (single/debate/ensemble) | 66.7 / 50.0 / 66.7% | **83.3 / 83.3 / 83.3%** |
| 우려 recall (ensemble) | 86.3% | **93.3%** |
| prec@3 (ensemble) | 53.3% | **60.0%** |
| precision | 41.7~51.2% | 46.5~50.3% |
| 위반원칙 재현율 (ensemble, 수정된 지표) | 90.0% | **90.0%** — 변화 없음 |
| **과잉위반** (pass 케이스 위반주장 수) | 2.00 / 3.00 / 3.00 | **1.50 / 2.50 / 2.50** ↓ |

**탐지력은 어느 것도 줄지 않았다.** 위험탐지 정확도는 91.7/83.3/91.7%로 완전 동일하고,
과잉위반은 3개 arm 모두 내려갔다 — 심각도 수정이 노린 효과의 직접 증거다.
유일한 실제 하락은 debate 단독의 원칙재현 85.0→75.0%인데 10건 중 1건 차이라 노이즈와
구분되지 않는다.

> 초기에 "위반원칙 재현율 83.3%→75.0% 하락"으로 보고했으나 **이는 지표 결함이었다**(결함 15번, 아래).

- **심각도 분산은 절반만 성공**: single은 흩어졌으나(치명18/중대68/주의14)
  ensemble은 여전히 중대 85%, 주의 0건.
- **83.3% = 10/12. 이전 8/12에서 2건 차이이고 시드 1회다.** 6-3(표본 확대) 전에는
  방향성 신호로만 다룰 것.
- 관대화 오류 여전히 0건 — 보수 편향 구조는 그대로.
- 남은 오답 2건 중 하나가 CASE-011(6-4의 그 케이스). **재라벨하면 11/12가 되지만
  결과에 맞춰 정답을 고치는 것이 되므로, 6-4는 측정과 분리해 판단해야 한다.**

### ~~6-2. 교차확인 × 심각도 4계층 노출~~ — 완료. **계층 서열까지 측정으로 검증됨**

계층 로직은 `concerns.py`에 단일 정의(`concern_tier`)로 두고 `report.py`·`ui/app.py`가 참조한다.

| 계층 | 조건 | 관측 정확도 (ensemble) |
|---|---|---|
| 🔴 즉시 조치 | 치명 + 교차확인 | 62.5% (5/8) |
| 🟠 우선 검토 | 치명 단독 · 중대 + 교차확인 | 53.3% (16/30) |
| 🟡 참고 | 중대 단독 | 31.8% (7/22) |
| ⚪ 접어두기 | 주의 이하 (교차확인이어도) | single 14.3% · debate 0.0% |

계층 서열은 검증됐다(3절). 수치는 12건·시드1회 잠정치이며 `TIER_CAVEAT`로
산출물에 표본 고지가 함께 나간다. 테스트가 고지 누락을 막는다.

**작업 중 드러난 사실 — 핸드오프의 "데이터는 있고 표시만 없다"는 틀렸다.**
`merge_concerns`/`sources`는 `benchmark.py`의 ensemble 경로에만 있었고,
`simulate.py` → `report.py` → `ui/app.py` 경로는 `aggregate()`가 `verdict.concerns`를
**통째로 버리고 있었다** (조용히 값을 잃는 유형 — 작업원칙 2번). 배관을 이었다:
`stamp_sources` → `ConsensusResult.concerns` → `SegmentResult.top_concerns`.

주의해서 유지할 것:
- **시드 반복(재현성)을 sources에 섞지 말 것.** 실측상 재현성은 정확성과 무관하다.
  반복 비율은 `concern_run_ratio`로 분리했고 테스트가 이를 고정한다.
- 세그먼트 내 페르소나 수가 많다고 교차확인으로 승격되지 않는다(`_segment_concerns`).
- `simulate`는 ensemble 모드가 없어 **항상 단독**이다. 산출물이 이 사실을 명시한다.
  교차확인 계층을 실제로 쓰려면 simulate에 ensemble 모드를 추가해야 한다 → **다음 후보**.

### 결함 15번 — 위반원칙 재현율이 과잉 경고를 보상하고 있었다 (수정 완료)

정답셋의 `principle` 필드는 라벨에 따라 **의미가 다르다.**

| 라벨 | `principle`의 뜻 |
|---|---|
| fail / warn | 실제로 **위반한** 원칙 |
| pass | 쟁점이 되었을 뿐 **위반하지 않은** 원칙 (CASE-006 "판매원칙 위반이 없다") |

둘을 같이 채점하니 **깨끗한 케이스에서 위반을 주장해야 점수를 받았다.**
실측: CASE-008(gold=pass)에서 모델이 '적합성 위반' 주장을 뺐는데 재현율이
100%→0%로 떨어졌다. 옳은 자제가 성능 하락으로 기록됐고, 그 1건이
ensemble 83.3%→75.0% 하락의 **전부**였다.

수정: `has_violation()`으로 pass를 채점 대상에서 빼고, pass 케이스의 과잉 주장은
`false_principle_rate`로 **따로 센다**(지우지 않고 분리 — 작업원칙 4).
`analyze_ablation.py`는 저장된 값을 쓰지 않고 outcomes에서 다시 계산하므로
**결함 15번 이전에 만든 결과 파일도 같은 기준으로 비교된다.**

`pass` 케이스가 2건뿐이라 과잉 경고 편향을 검출할 수 없다.

## 8. 작업 원칙 (이 프로젝트에서 지켜온 것)

1. **측정 없이 개선을 주장하지 않는다.** 가설 7개가 측정으로 뒤집혔다.
2. **조용히 잘못된 값을 만드는 코드를 경계한다.** 고친 결함 15건 중 6건이 그 유형이었다
   (스키마 무시 → 기본값 50점, 미기재 → "없음" 단정, 컨텍스트 초과 → 잘림 등).
3. **데이터 부재를 부정 사실로 해석하지 않는다.** `None`(모름)과 `False`(아니오)를 구분한다.
4. **지우지 않고 정렬한다.** 우려는 기각보다 계층화가 안전하다(놓치면 책임, 많으면 무시).
5. **가공 데이터에는 표시를 남긴다.** `[MOCK]`, `_meta.caveat`, `조정사례(가공)`.
